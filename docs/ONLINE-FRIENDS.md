# เพื่อนผู้เล่นแบบออนไลน์ (แผนอัปเกรดจากลิงก์เชิญ → เรียลไทม์ด้วย Firebase)

สถานะตอนนี้ (v30): เพื่อนผู้เล่นใช้ลิงก์เชิญ (`#f` / `#g` / `#t`) กล่องจดหมาย และทริปด้วยกัน ทั้งหมดอยู่ในเครื่องผู้เล่น ไม่มีเซิร์ฟเวอร์ (ดู `game-friends.js`)
เพื่อนบ้าน NPC (`game-neighbors.js`) ไม่เกี่ยวกับเอกสารนี้ และไม่ต้องใช้เซิร์ฟเวอร์

เอกสารนี้ใช้ตัดสินใจว่า **จะทำอะไร ก่อน-หลัง** ถ้าจะให้เพื่อนเห็นกันแบบออนไลน์จริง
ไม่ใช่คำปรึกษาทางกฎหมาย ส่วน PDPA ต้องให้ทนายและ DPO ตรวจก่อนเปิดจริง

---

## 0. สรุปการตัดสินใจ (อ่านส่วนนี้ก่อน)

| คำถาม | คำตอบที่แนะนำ |
|---|---|
| ควรทำออนไลน์ไหม | ทำเมื่อมีผู้เล่นจริงที่ใช้ลิงก์เชิญสม่ำเสมอ (เช่น ≥ 200 คู่เพื่อนที่ส่งจดหมายกันใน 30 วัน) ก่อนหน้านั้นลิงก์เชิญพอแล้ว |
| ใช้อะไร | Firebase: Anonymous Auth + Cloud Firestore + Security Rules + App Check · Cloud Functions เฉพาะงานคัดกรอง/จำกัดอัตรา (ต้องใช้แผน Blaze) |
| ข้อความแบบไหน | **ข้อความสำเร็จรูปก่อน (preset-first)** ไม่มีช่องพิมพ์อิสระในระยะแรก |
| เก็บข้อมูลที่ไหน | Firestore ภูมิภาค **asia-southeast3 (กรุงเทพฯ)** เพื่อลดเรื่องส่งข้อมูลข้ามประเทศ (เลือกตอนสร้างฐานข้อมูล เปลี่ยนทีหลังไม่ได้) |
| อายุ | 18+ ตามเดิม ยืนยันด้วยการติ๊กยอมรับ (ไม่เก็บวันเกิด) |
| ห้ามส่งขึ้นเซิร์ฟเวอร์ | อารมณ์รายวัน, ผลแบบประเมิน (2Q/9Q/CBI/18 ข้อ), แชตกับน้อง, เรื่องที่หนักใจ, สถานะเสี่ยง (`hikariCare_`) ทุกอย่างยังอยู่ในเครื่อง |
| ค่าใช้จ่าย | ช่วงเริ่ม (≤ ~1,000 ผู้เล่นต่อวัน) น่าจะอยู่ในโควตาฟรี · ต้องเปิด Blaze ถ้าใช้ Cloud Functions + ตั้ง budget alert |

ลำดับงาน: **ขั้น 1 → 2 → 3 → 4** (ข้ามขั้นไม่ได้ โดยเฉพาะขั้น 2 ต้องเสร็จก่อนมีข้อความระหว่างผู้ใช้)

## 1. ขั้น 1: บัญชีนิรนาม + เพื่อน + สถานะออนไลน์ (ยังไม่มีข้อความอิสระ)

### 1.1 ตั้งค่าโปรเจกต์
1. สร้างโปรเจกต์ Firebase แยก 2 ตัว: `hikari-dev` และ `hikari-prod`
2. เปิด **Authentication → Anonymous** (ผู้เล่นไม่ต้องสมัคร ไม่เก็บอีเมล/เบอร์)
3. สร้าง **Cloud Firestore (Standard)** ที่ `asia-southeast3` (Bangkok)
4. เปิด **App Check** (reCAPTCHA Enterprise สำหรับเว็บ) และบังคับใช้กับ Firestore เพื่อกันสคริปต์ยิงตรง
5. ใส่ค่า config ของ Firebase ใน `config.js` (ค่า apiKey ของเว็บไม่ใช่ความลับ ความปลอดภัยอยู่ที่ Rules + App Check)
6. ไม่เพิ่ม Analytics / ads SDK ในเกม (ข้อมูลใจเป็นข้อมูลอ่อนไหว)

### 1.2 โครงข้อมูล (เก็บน้อยที่สุด)
```
users/{uid}            { nick, world, avatar, lang, createdAt, consentV, adult:true, blocked:[uid…] (≤ 200) }
friendCodes/{code}     { uid, expiresAt }                       // โค้ดเชิญ 8 ตัว หมดอายุ 7 วัน
friends/{pairId}       { a, b, since }                         // pairId = uid เล็ก + "_" + uid ใหญ่
presence/{uid}         { state: "online"|"away", place, at }   // place = รหัสฉากเท่านั้น
mail/{uid}/inbox/{id}  { from, preset, sticker, at }            // preset = รหัสข้อความสำเร็จรูป ไม่ใช่ข้อความ
rooms/{roomId}         { stop, members:[uid,uid], createdBy, at, expiresAt }   // ทริปด้วยกัน
reports/{id}           { by, target, kind, refPath, at, status }
```
- `nick` = ชื่อเล่นจากรายการคำ (เช่น "แมวส้ม 42") หรือพิมพ์เองแต่ผ่าน `HikariSafety` + ตัวกรองคำหยาบ + ยาวไม่เกิน 16 ตัว
- ไม่มีรูปโปรไฟล์อัปโหลด ใช้ภาพน้องในเกมเท่านั้น
- ข้อมูลที่ซิงก์ขึ้นได้: ชื่อเล่น โลก ของที่แต่ง สถานะออนไลน์ จดหมายสำเร็จรูป **เท่านั้น**

### 1.3 Security Rules (โครงร่าง ต้องเขียนเทสต์ด้วย Emulator ก่อนใช้)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function signedIn() { return request.auth != null; }
    function me(uid) { return signedIn() && request.auth.uid == uid; }
    function pair(a, b) { return a < b ? a + "_" + b : b + "_" + a; }
    function isFriend(other) { return exists(/databases/$(db)/documents/friends/$(pair(request.auth.uid, other))); }
    function blockedBy(other) { return request.auth.uid in get(/databases/$(db)/documents/users/$(other)).data.blocked; }

    match /users/{uid} {
      allow read: if signedIn() && (me(uid) || isFriend(uid));
      allow create, update: if me(uid)
        && request.resource.data.keys().hasOnly(['nick','world','avatar','lang','createdAt','consentV','adult','blocked'])
        && request.resource.data.nick is string && request.resource.data.nick.size() <= 16
        && request.resource.data.adult == true
        && request.resource.data.blocked.size() <= 200;
      allow delete: if me(uid);
    }
    match /presence/{uid} {
      allow read: if signedIn() && isFriend(uid) && !blockedBy(uid);
      allow write: if me(uid) && request.resource.data.keys().hasOnly(['state','place','at']);
    }
    match /mail/{to}/inbox/{id} {
      allow read, delete: if me(to);
      allow create: if signedIn() && isFriend(to) && !blockedBy(to)
        && request.resource.data.from == request.auth.uid
        && request.resource.data.keys().hasOnly(['from','preset','sticker','at'])
        && request.resource.data.preset is int && request.resource.data.preset < 200   // รหัสในรายการสำเร็จรูปเท่านั้น
        && request.resource.data.at == request.time;
      allow update: if false;
    }
    match /rooms/{roomId} {
      allow read: if signedIn() && request.auth.uid in resource.data.members;
      allow create: if signedIn() && request.resource.data.createdBy == request.auth.uid
        && request.resource.data.members.size() == 2 && request.auth.uid in request.resource.data.members;
      allow update: if signedIn() && request.auth.uid in resource.data.members
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['stop','at']);
    }
    match /reports/{id} {
      allow create: if signedIn() && request.resource.data.by == request.auth.uid;
      allow read, update, delete: if false;          // อ่านได้เฉพาะทีมผ่าน Admin SDK / คอนโซล
    }
    match /friends/{p} { allow read: if signedIn() && request.auth.uid in resource.data.values(); allow write: if false; } // สร้างผ่าน Function เท่านั้น
    match /friendCodes/{c} { allow read, write: if false; }                                                              // ผ่าน Function เท่านั้น
  }
}
```
- การรับเพื่อน (ใช้โค้ดเชิญ) ทำใน **Callable Function** `acceptInvite(code)`: ตรวจโค้ด หมดอายุ ไม่ใช่ตัวเอง ไม่ถูกบล็อก แล้วสร้าง `friends/{pairId}`
- `get()` / `exists()` ใน Rules นับเป็นการอ่าน 1 ครั้ง (คิดในค่าใช้จ่าย)

### 1.4 สถานะออนไลน์ (presence)
- ใช้ Firestore อย่างเดียว: เขียน `presence/{uid}` เมื่อเปิดเกม/กลับมาที่แท็บ และทุก 5 นาทีขณะเปิด ถือว่า "ออนไลน์" ถ้า `at` ไม่เกิน 6 นาที (ไม่ต้องใช้ Realtime Database)
- ปิดได้ในตั้งค่า: "ซ่อนสถานะออนไลน์" (ค่าเริ่มต้น = ซ่อน ให้ผู้เล่นเลือกเปิดเอง)
- ไม่แสดงเวลาออนไลน์ล่าสุดแบบละเอียด (เลี่ยงความกดดัน "อ่านแล้วไม่ตอบ")

### 1.5 เทสต์ก่อนปล่อยขั้น 1
- Emulator: ผู้ใช้ A อ่าน `users/B` ไม่ได้ถ้าไม่ใช่เพื่อน · ส่งจดหมายหาคนที่บล็อกไม่ได้ · ส่ง `preset` ที่ไม่ใช่ตัวเลขไม่ได้ · แก้จดหมายไม่ได้
- ปิดเน็ต: เกมเล่นต่อได้ทุกอย่าง (ออนไลน์เป็นส่วนเสริม)

## 2. ขั้น 2: ความปลอดภัยระหว่างผู้ใช้ (ต้องเสร็จก่อนมีข้อความใด ๆ ที่ไม่ใช่ preset)

### 2.1 บล็อก / รายงาน (ทำพร้อมขั้น 1 เลย)
- ทุกการ์ดเพื่อนมีปุ่ม **บล็อก** และ **รายงาน** แตะครั้งเดียว ไม่ต้องอธิบายเหตุผล
- บล็อก = เพิ่ม uid ใน `blocked` + ลบ `friends/{pairId}` (ผ่าน Function) + ซ่อนจดหมายจากคนนั้นทันทีในเครื่อง ไม่แจ้งอีกฝ่าย
- รายงาน: เลือกหมวด (คุกคาม / เนื้อหาไม่เหมาะสม / สแปม / **เป็นห่วงความปลอดภัยของเพื่อน**) แล้วสร้าง `reports/{id}`

### 2.2 คิวตรวจ (moderation queue)
- Function `onReportCreate` ส่งแจ้งเตือนเข้าอีเมลทีม/ช่อง Slack ภายใน (ไม่ใส่ข้อความส่วนตัวในแจ้งเตือน ใส่แค่ลิงก์คอนโซล)
- เป้าเวลา: หมวด "เป็นห่วงความปลอดภัย" ดูภายใน 24 ชม. หมวดอื่นภายใน 72 ชม.
- ผลตรวจ: ไม่มีอะไร / เตือน / ระงับ 7 วัน / ปิดบัญชี บันทึกใน `status` (เก็บ log 1 ปี แล้วลบ)
- ผู้ตรวจต้องผ่านอบรมสั้น: safe messaging (WHO/AFSP), ไม่ตัดสิน, ไม่ติดต่อผู้ใช้เอง

### 2.3 จำกัดอัตรา (rate limits)
| สิ่งที่ทำ | ขีดจำกัดเริ่มต้น | ทำที่ |
|---|---|---|
| ส่งจดหมายสำเร็จรูป | 20 ฉบับ/วัน/คน, 3 ฉบับ/วัน/เพื่อน 1 คน | Rules (เก็บตัวนับรายวันใน `users/{uid}`) หรือ Function |
| สร้างโค้ดเชิญ | 10 โค้ด/วัน | Function |
| รับเพื่อน | เพื่อนสูงสุด 50 คน | Function |
| สร้างห้องทริป | 10 ห้อง/วัน, ห้องหมดอายุ 2 ชม. | Rules + TTL policy |
| รายงาน | 10 ครั้ง/วัน | Function |
- เปิด TTL policy ที่ `expiresAt` ของ `friendCodes` และ `rooms` ให้ลบเองอัตโนมัติ

### 2.4 ข้อความ: preset-first
- ระยะแรก **ไม่มีช่องพิมพ์อิสระ** ส่งได้เฉพาะข้อความสำเร็จรูปที่ทีมเขียน 10 ภาษา (เช่น "คิดถึงนะ", "วันนี้พักบ้างนะ", "ส่งกำลังใจให้", "ไปเที่ยวด้วยกันไหม") + สติกเกอร์
- ข้อดี: ไม่มีข้อความคุกคาม ไม่ต้องแปล ไม่ต้องคัดกรองเนื้อหา ข้อมูลอ่อนไหวไม่ขึ้นเซิร์ฟเวอร์
- ถ้าภายหลังจะเปิดข้อความอิสระ ต้องมีครบก่อน: ตรวจด้วย `HikariSafety.hasRiskText` + `hasAbuseText` ทั้งฝั่งส่ง (ในเครื่อง) และฝั่งเซิร์ฟเวอร์ (Function) · ตัวกรองคำหยาบ 10 ภาษา · จำกัดยาว 140 ตัว · ห้ามลิงก์/เบอร์โทร · ผู้รับต้องเปิดรับข้อความอิสระเอง

### 2.5 เมื่อมีสัญญาณวิกฤตระหว่างผู้ใช้ (incident response)
กรณีที่เป็นไปได้: เพื่อนรายงานว่า "เป็นห่วงความปลอดภัย" หรือ (ถ้าเปิดข้อความอิสระ) ข้อความเข้า `hasRiskText`

1. **ฝั่งผู้ส่ง (ในเครื่อง ทันที)**: แสดงการ์ดช่วยเหลือแบบเดิม (1323 / 1669 / findahelpline) ด้วยข้อความคงที่ที่มนุษย์เขียน ไม่บล็อกการส่ง ไม่ดุ เรียก `markRisk()`
2. **ฝั่งผู้รับ**: เห็นข้อความพร้อมการ์ด "เพื่อนอาจกำลังลำบาก" + วิธีช่วยแบบสั้น (ฟัง ไม่ตัดสิน ชวนโทร 1323 ด้วยกัน ถ้าอันตรายเร่งด่วนโทร 1669/191) + บอกชัดว่า "คุณไม่ต้องรับผิดชอบคนเดียว"
3. **ระบบ**: สร้างรายงานอัตโนมัติหมวด "ความปลอดภัย" (เก็บแค่ uid + เวลา + รหัส preset ไม่เก็บข้อความถ้าไม่จำเป็น) และซ่อนการขายเงินจริงจากทั้งสองฝั่ง (`inDistress()`)
4. **ทีม (ภายใน 24 ชม.)**: ตรวจตามคู่มือ ไม่ติดต่อผู้ใช้เองนอกแอป ไม่ส่งข้อมูลให้บุคคลที่สาม เว้นแต่มีหมายศาล/คำขอจากเจ้าหน้าที่ตามกฎหมาย หรือมีอันตรายร้ายแรงต่อชีวิตตาม PDPA มาตรา 24(2) / 26(1) (ปรึกษาทนายก่อน)
5. **บันทึกเหตุการณ์**: เวลา ผู้ตรวจ ผล ทบทวนทุกเดือนกับนักจิตวิทยาคลินิกที่ปรึกษา
6. ห้ามใช้ AI แต่งข้อความวิกฤตเอง ห้ามให้ผู้ใช้คนอื่นเห็นว่าใครถูกรายงาน

## 3. ขั้น 3: ทริปด้วยกันแบบเรียลไทม์

- ห้อง `rooms/{roomId}` สมาชิก 2 คน (เพื่อนกันเท่านั้น) ฟังการเปลี่ยนแปลงด้วย `onSnapshot`
- ซิงก์เฉพาะ: สถานที่ (`stop`), ตำแหน่งน้อง (ปัดเป็นช่อง 5% ส่งไม่เกิน 1 ครั้ง/2 วินาที), อีโมต/สติกเกอร์สำเร็จรูป
- ไม่มีแชตในห้อง ใช้อีโมตแทน (หัวใจ โบกมือ หายใจด้วยกัน)
- "หายใจด้วยกัน 1 นาที": คนหนึ่งกดเริ่ม อีกคนเห็นจังหวะเดียวกัน (ส่งแค่เวลาเริ่ม)
- ห้องหมดอายุ 2 ชม. (TTL) ออกจากห้องได้ทุกเมื่อ ไม่มีการลงโทษ
- ประเมินอ่าน/เขียน: 2 คน × ทริป 10 นาที × เขียนตำแหน่ง 1 ครั้ง/2 วิ ≈ 600 เขียน + 600 อ่านต่อทริป → ถ้ามี 30 ทริป/วัน ก็เกินโควตาเขียนฟรีแล้ว (20,000/วัน) ดังนั้น **ส่งตำแหน่งเฉพาะตอนแตะเดิน** (ไม่ใช่ทุก 2 วินาที) เหลือราว 30–60 เขียนต่อทริป

## 4. ขั้น 4: ขยายตัว

- เปิดข้อความอิสระ (ถ้าจำเป็นจริง) ตามเงื่อนไขข้อ 2.4
- แดชบอร์ดผู้ดูแล (หน้าเว็บภายในที่ใช้ Admin SDK ผ่าน Function มีสิทธิ์ตามบทบาท)
- ทบทวนตัวเลขค่าใช้จ่ายทุกเดือน ถ้าอ่านเยอะ: แคชรายชื่อเพื่อนในเครื่อง ลดการฟังแบบเรียลไทม์ให้เหลือเฉพาะหน้าที่เปิดอยู่

## 5. PDPA (ประเด็นที่ต้องทำ)

| เรื่อง | ต้องทำ |
|---|---|
| ฐานทางกฎหมาย | ข้อมูลเพื่อน/ชื่อเล่น/สถานะ = ข้อมูลส่วนบุคคลทั่วไป ใช้ฐานสัญญา (ให้บริการฟีเจอร์ที่ผู้ใช้ขอ) + ความยินยอมสำหรับสิ่งที่ไม่จำเป็น (เช่น แสดงสถานะออนไลน์) · ข้อมูลสุขภาพใจ **ไม่ขึ้นเซิร์ฟเวอร์** ถ้าวันหนึ่งต้องขึ้น ต้องขอความยินยอมโดยชัดแจ้งแยกต่างหาก (มาตรา 26) |
| ความยินยอม | หน้าจอเปิดใช้ "เพื่อนออนไลน์" แยกจากการเล่นปกติ อธิบายสั้น ๆ ว่าเก็บอะไร เก็บที่ไหน ลบได้อย่างไร ไม่ติ๊กไว้ให้ก่อน เก็บเวอร์ชันนโยบาย (`consentV`) ถอนได้ทุกเมื่อ (ถอน = ออฟไลน์เหมือนเดิม) |
| อายุ | เกมนี้สำหรับ 18+ แต่ในกฎหมายไทยบรรลุนิติภาวะที่ 20 ปี (ผู้เยาว์ต้องให้ผู้ใช้อำนาจปกครองยินยอมในบางกรณี มาตรา 20) → ให้ทนายตัดสินว่าจะจำกัดฟีเจอร์ออนไลน์ไว้ที่ 20+ หรือมีขั้นตอนเพิ่ม · ยืนยันด้วยการติ๊ก ไม่เก็บวันเกิด |
| เก็บน้อยที่สุด | ตามข้อ 1.2 เท่านั้น ไม่มีอีเมล เบอร์ ตำแหน่งจริง รูป หรือข้อความอิสระ |
| ลบข้อมูล | ปุ่ม "ลบบัญชีออนไลน์" ในแท็บฉัน → Function ลบ `users`, `presence`, `mail`, `friends`, `rooms` ของ uid นั้น + ลบบัญชี Auth ภายใน 30 วัน (รายงานเก็บแบบไม่ระบุตัวตนได้ 1 ปีเพื่อความปลอดภัย) · บัญชีนิรนามที่ไม่ใช้ 12 เดือน ลบอัตโนมัติ |
| สิทธิ์เจ้าของข้อมูล | ขอดู/ขอสำเนา/ขอลบ/คัดค้าน ผ่านอีเมลบริษัท ตอบภายใน 30 วัน |
| DPO | บริการนี้เกี่ยวกับสุขภาวะทางใจ ถ้าจะประมวลผลข้อมูลอ่อนไหวเป็นกิจกรรมหลักหรือจำนวนมาก ต้องมี DPO (มาตรา 41) แต่งตั้งไว้ก่อนเปิดออนไลน์ (จ้างภายนอกได้) และแจ้งช่องทางติดต่อในนโยบาย |
| ส่งข้อมูลข้ามประเทศ | เก็บ Firestore ที่กรุงเทพฯ ลดปัญหาได้มาก แต่ Firebase Auth / App Check / Functions บางส่วนอาจประมวลผลนอกประเทศ → อ้างอิงประกาศ คกก. คุ้มครองข้อมูลส่วนบุคคลเรื่องการส่งข้อมูลไปต่างประเทศ (มาตรา 28/29 มีผล 24 มี.ค. 2567): ใช้ข้อสัญญามาตรฐาน (Cloud Data Processing Addendum ของ Google) และระบุในนโยบายความเป็นส่วนตัว |
| สัญญาผู้ประมวลผล | ยอมรับ Google Cloud Data Processing Addendum ในคอนโซล · จดรายชื่อผู้ประมวลผลย่อย |
| บันทึกกิจกรรม (ROPA) | ทำตารางกิจกรรมการประมวลผล (มาตรา 39) ก่อนเปิด |
| เหตุละเมิด | แจ้ง สคส. ภายใน 72 ชม. ที่ทราบเหตุ (มาตรา 37(4)) ถ้าเสี่ยงสูงแจ้งผู้ใช้ด้วย · เตรียมแบบฟอร์มและผู้รับผิดชอบไว้ก่อน |

## 6. ค่าใช้จ่าย (ตัวเลขจากหน้า Firebase/Google Cloud ณ 7 พ.ย. 2026 ต้องตรวจซ้ำก่อนตัดสินใจ)

**โควตาฟรี (ใช้ได้ทั้ง Spark และ Blaze)**
- Firestore (Standard): เก็บ 1 GiB · อ่าน 50,000/วัน · เขียน 20,000/วัน · ลบ 20,000/วัน · ส่งข้อมูลออก 10 GiB/เดือน · ฟรีเฉพาะฐานข้อมูล default 1 ตัวต่อโปรเจกต์ · โควตารีเซ็ตเที่ยงคืนเวลาแปซิฟิก
- Authentication: 50,000 MAU ฟรี (ไม่มีขีดแยกสำหรับนิรนามบนหน้าราคา)
- Hosting: 10 GB เก็บ · 360 MB/วัน (เกมยังอยู่ GitHub Pages ได้ ไม่ต้องย้าย)
- App Check: ไม่มีค่าใช้จ่าย แต่มีโควตาตามผู้ยืนยัน (reCAPTCHA Enterprise มีโควตาฟรีรายเดือนของตัวเอง)

**Spark (ฟรี ไม่ผูกบัตร)**: เกินโควตา = บริการนั้นหยุดจนรีเซ็ต · **ใช้ Cloud Functions ไม่ได้** → ทำรับเพื่อน/จำกัดอัตรา/คิวตรวจฝั่งเซิร์ฟเวอร์ไม่ได้ เหมาะแค่ทดลองภายใน

**Blaze (จ่ายตามใช้)**: ได้โควตาฟรีเท่าเดิม + Functions (2 ล้านครั้ง/เดือนฟรี จากนั้น $0.40 ต่อล้านครั้ง) · Firestore ส่วนเกินตามราคา Google Cloud (หน้าเว็บ ณ วันที่ตรวจ: อ่าน ~$0.03, เขียน ~$0.09, ลบ ~$0.01 ต่อ 100,000 ครั้ง; ตรวจ SKU ของภูมิภาคกรุงเทพฯ อีกครั้ง) · **budget alert แค่แจ้งเตือน ไม่ได้ตัดการใช้** ต้องตั้ง alert ที่ 50/90/100% และมีสคริปต์/ขั้นตอนปิดฟีเจอร์ออนไลน์เองถ้าพุ่ง

**ประมาณการ (ผู้เล่นออนไลน์ต่อวัน, หลังทำแคชแล้ว)**
| ผู้เล่น/วัน | อ่าน/วัน | เขียน/วัน | อยู่ในโควตาฟรี? | ส่วนเกินโดยประมาณ/เดือน |
|---|---|---|---|---|
| 300 | ~15,000 | ~3,000 | ใช่ | 0 |
| 1,000 | ~50,000 | ~10,000 | ชนเพดานอ่าน | < $1 |
| 10,000 | ~500,000 | ~100,000 | ไม่ | ราว $4–6 (Firestore) + Functions เล็กน้อย |
| 100,000 | ~5,000,000 | ~1,000,000 | ไม่ | ราว $70–80 + reCAPTCHA ถ้าเกินโควตา |
สมมติฐาน: ผู้เล่น 1 คนเปิดเกม 2 ครั้ง/วัน อ่านรายชื่อเพื่อน+สถานะ+กล่องจดหมาย ~50 ครั้ง เขียน ~10 ครั้ง (รวม `get()` ใน Rules) ตัวเลขจริงต้องวัดจาก Usage tab หลังทดลอง 2 สัปดาห์

## 7. เช็กลิสต์ก่อนเปิดจริง

- [ ] Rules ผ่านเทสต์ Emulator ครบทุกกรณีในข้อ 1.5 และ 2
- [ ] App Check บังคับใช้แล้ว
- [ ] บล็อก/รายงาน ใช้งานได้ คิวตรวจมีคนรับผิดชอบและเวรสำรอง
- [ ] ข้อความ preset 10 ภาษา ผ่านนักจิตวิทยาคลินิกและเจ้าของภาษา ไม่มีข้อความเข้า `hasRiskText`/`hasAbuseText`
- [ ] นโยบายความเป็นส่วนตัว + หน้าความยินยอม ผ่านทนาย · แต่งตั้ง DPO · ทำ ROPA
- [ ] ปุ่มลบบัญชีออนไลน์ทำงานจริง (ทดสอบแล้วข้อมูลหายจากคอนโซล)
- [ ] Budget alert + ขั้นตอนปิดฟีเจอร์ฉุกเฉิน (feature flag ใน `config.js`)
- [ ] ปิดเน็ตแล้วเกมเล่นได้ครบ ข้อมูลใจไม่เคยขึ้นเซิร์ฟเวอร์ (ตรวจ Network tab)
- [ ] ปุ่มช่วยเหลือแตะได้ทุกหน้าจอใหม่
