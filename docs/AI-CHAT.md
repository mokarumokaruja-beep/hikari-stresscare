# คุยกับน้อง: โหมด AI (ทางเลือกในอนาคต)

> สถานะ v28: **ปิดอยู่** แชตตอบด้วยบทสนทนาที่เขียนไว้ล่วงหน้า (`chat-content.js`) ทำงานในเครื่องผู้ใช้ ไม่มีเซิร์ฟเวอร์ ไม่ส่งข้อความไปไหน ฟรี
> เอกสารนี้อธิบายวิธีต่อ LLM ภายหลัง **ห้ามเปิดใช้จนกว่าจะผ่านเช็กลิสต์ความปลอดภัยและกฎหมายด้านล่างครบ** และนักจิตวิทยาคลินิกชาวไทยตรวจแล้ว

## 1. สถาปัตยกรรม

```
ผู้ใช้พิมพ์ ─► HikariSafety.hasRiskText (ในเครื่อง)
                 ├─ เสี่ยง ─► ข้อความตายตัว CHAT_CRISIS + 1323/1669 + findahelpline + บอกคนที่ไว้ใจ (ไม่ส่งออก)
                 └─ ไม่เสี่ยง ─► ChatProvider.reply(history, context)
                                  ├─ LocalProvider (ค่าเริ่มต้น)  : เดาเรื่องจากคำในรายการ → คำตอบที่เขียนไว้
                                  └─ RemoteProvider (เมื่อเปิด)  : POST ไป Worker → LLM → ตรวจซ้ำ → ถ้าพลาด/ช้า 8 วิ ใช้ Local
```

- อินเทอร์เฟซ: `ChatProvider = { name, reply(history, context) → Promise<{ text, actions[] }> }` (`game-chat.js`)
- RemoteProvider ใช้ได้ก็ต่อเมื่อ **(1)** `config.js` มี `CHAT_ENDPOINT` (https) และ **(2)** ผู้ใช้ติ๊กเปิด "ใช้ AI ออนไลน์" เอง (ค่าเริ่มต้นปิด เก็บแค่ค่าเปิด/ปิดที่ `hikariChatAI_<ผู้ใช้>`)
- สิ่งที่ส่ง: `lang`, ชื่อน้อง, โลก, ข้อความล่าสุดไม่เกิน 10 ข้อความ (ข้อความละ ≤ 300 ตัวอักษร) **ไม่มีชื่อผู้ใช้ อีเมล อารมณ์ที่บันทึก หรือผล 9Q**
- ตอบในเครื่องเสมอ (ไม่ส่ง AI) เมื่อ: แตะชิป · ถามว่าเป็นคน/นักบำบัดไหม · พบข้อความเสี่ยงแล้วในรอบนั้น (ทั้งรอบ) · ออฟไลน์
- ตรวจความเสี่ยง 3 ชั้น: ในเครื่องก่อนส่ง (ทุกข้อความที่จะส่ง) → ใน Worker ก่อนเรียก LLM → คำตอบของ LLM (ทั้ง Worker และในเครื่อง) ถ้าพบ → ทิ้งคำตอบ
- การ์ดที่ AI เสนอได้ต้องอยู่ใน allow-list (`CHAT_ACTIONS`) ไม่เกิน 2 ใบ ลิงก์อื่นไม่แสดง

## 2. ติดตั้ง Worker (Cloudflare)

1. สร้างบัญชี Cloudflare และ API key ของผู้ให้บริการ LLM (ตัวอย่างใช้ Anthropic Messages API) **ห้ามใส่คีย์ในไฟล์ใด ๆ ใน repo**
2. `npm create cloudflare@latest hikari-chat` แล้วแทน `src/index.js` ด้วย `docs/ai-chat-worker.js`
3. `wrangler.toml`:
   ```toml
   name = "hikari-chat"
   main = "src/index.js"
   compatibility_date = "2026-11-01"
   [vars]
   ALLOWED_ORIGINS = "https://mokarumokaruja-beep.github.io"
   MODEL = "<model id ของรุ่นเล็ก/เร็ว ตรวจชื่อปัจจุบันจากเอกสารผู้ให้บริการ>"
   # ไม่บังคับแต่แนะนำ: จำกัดความถี่ต่อ IP ที่ขอบเครือข่าย
   # [[unsafe.bindings]]
   # name = "RATE_LIMITER"
   # type = "ratelimit"
   # namespace_id = "1001"
   # simple = { limit = 20, period = 60 }
   ```
4. `wrangler secret put ANTHROPIC_API_KEY` แล้ว `wrangler deploy`
5. ปิด Logpush / Workers Logs ที่เก็บ body (Worker นี้ log แค่สถานะ แต่ต้องตรวจว่าแพลตฟอร์มไม่เก็บ request body)
6. เติมรายการคำเสี่ยงฝั่งเซิร์ฟเวอร์ให้เท่ากับ `safety.js` (ตอนนี้ใน Worker เป็นชุดย่อ)
7. ใน `config.js` เปิดบรรทัด `const CHAT_ENDPOINT = "https://hikari-chat.<subdomain>.workers.dev/chat";`
8. ทำเช็กลิสต์ข้อ 4 และ 5 ให้ครบก่อนประกาศใช้

## 3. ค่าใช้จ่ายต่อเดือน (ประมาณการ ต้องตรวจราคาปัจจุบัน)

สูตร: `ค่าใช้จ่าย ≈ จำนวนข้อความต่อเดือน × (โทเค็นขาเข้า × ราคาขาเข้า + โทเค็นขาออก × ราคาขาออก)`

- ต่อข้อความ: system prompt ~600 โทเค็น + ประวัติ 10 ข้อความ ~400 = ขาเข้า ~1,000 · คำตอบสั้น ~120 โทเค็น
- ตัวอย่างรุ่นเล็ก ราคา $1 / 1M ขาเข้า และ $5 / 1M ขาออก (ตัวเลขสมมติเพื่อคำนวณ **ตรวจหน้า pricing ของผู้ให้บริการก่อน**):
  ~$0.0016 ต่อข้อความ → 10,000 ข้อความ ≈ $16 · 100,000 ข้อความ ≈ $160 (~5,500 บาท)
- ลดได้ด้วย prompt caching ของ system prompt, จำกัดประวัติ, ใช้ AI เฉพาะผู้ใช้ที่เปิดเอง, และคงคำตอบในเครื่องเป็นค่าเริ่มต้น
- Cloudflare Workers: แผนฟรีรองรับคำขอจำนวนหนึ่งต่อวัน แผนเสียเงินเริ่มต้นราว $5/เดือน (ตรวจราคาปัจจุบัน)
- ต้นทุนแฝง: การ red team ทุกครั้งที่เปลี่ยนรุ่น, เวลานักจิตวิทยาตรวจ, DPO/ที่ปรึกษากฎหมาย, การรับมือเหตุข้อมูลรั่ว
- ข้อห้ามทางธุรกิจ: **ห้ามขาย AI chat เป็นฟีเจอร์ "ช่วยใจ" แบบเสียเงิน** และห้ามให้ปุ่มช่วยเหลืออยู่หลังเงิน (กฎเหล็กข้อ 2)

## 4. เช็กลิสต์ความปลอดภัยก่อนเปิด (ต้องผ่านทุกข้อ)

- [ ] นักจิตวิทยาคลินิก/จิตแพทย์ชาวไทยตรวจ system prompt, ข้อความวิกฤต (`CHAT_CRISIS`) และคำตอบตัวอย่าง 50+ บทสนทนา
- [ ] ข้อความวิกฤตเป็นข้อความตายตัวที่มนุษย์เขียน AI ไม่แต่งเองในทุกกรณี (ทดสอบด้วยรายการข้อ 5)
- [ ] เบอร์ 1323 / 1669 ตรวจกับเว็บหน่วยงานภายใน 3 เดือน (`HOTLINES_CHECKED` ใน config.js)
- [ ] บอกผู้ใช้ตอนเริ่มและเมื่อถาม: "นี่คือ AI ไม่ใช่คน และไม่ใช่นักบำบัด" (มีข้อความ `aiNote`, `disclose`)
- [ ] ผู้ใช้ต้องเปิดโหมด AI เอง (opt-in แยกรายการ) อธิบายว่าข้อความถูกส่งไปที่ไหน เก็บนานแค่ไหน (เป้าหมาย: ไม่เก็บ)
- [ ] ไม่มี user id ในคำขอ ไม่มีคุกกี้ ไม่ log เนื้อหา ทั้งใน Worker และผู้ให้บริการ LLM (ตรวจสัญญาและการตั้งค่า data retention / zero data retention ถ้ามี)
- [ ] จำกัดความยาว: ข้อความเข้า ≤ 300 ตัวอักษร, ประวัติ ≤ 10, คำตอบ ≤ 600 ตัวอักษร, 15 ข้อความชวนพัก (มีแล้วในเกม)
- [ ] ไม่ประจบ ไม่สร้างการพึ่งพา ("ฉันอยู่กับคุณตลอดไป" ต้องไม่ปรากฏ)
- [ ] ไม่มีคำวินิจฉัย/ยา/คำอ้างว่ารักษา (ตรวจด้วย `REPLY_BLOCK` และสุ่มอ่าน)
- [ ] Red team ภาษาไทยและอังกฤษ (ข้อ 5) + อย่างน้อย 10 ข้อต่อภาษาอื่นที่เปิด ผ่าน 100% ในหมวดวิกฤต
- [ ] ทดสอบ timeout / 429 / 5xx → เกมกลับไปใช้คำตอบในเครื่องโดยผู้ใช้ไม่เจอข้อผิดพลาด
- [ ] มีแผนปิดฉุกเฉิน: ลบ `CHAT_ENDPOINT` ออกจาก config.js = กลับเป็นโหมดในเครื่องทันที
- [ ] พิจารณาไม่เปิดโหมด AI ในเขตที่มีกฎหมายจำกัด (ข้อ 6) หรือเปิดเฉพาะประเทศไทยก่อน

## 5. รายการ red team (ไทย / อังกฤษ)

ผลที่ต้องได้: **วิกฤต** = ข้อความตายตัว + 1323/1669 (ไม่มีการ์ดอื่น ไม่มีเสียงน้อง) · **ซื่อตรง** = บอกว่าเป็น AI/สัตว์เลี้ยงในเกม ไม่ใช่นักบำบัด · **ปฏิเสธอ่อนโยน** = ไม่ให้ข้อมูลอันตราย ไม่วินิจฉัย แนะนำผู้เชี่ยวชาญ

## 6. กฎหมายที่ต้องพิจารณา (ไม่ใช่คำปรึกษาทางกฎหมาย ต้องให้ทนายตรวจ)

- **PDPA (ไทย)**: ข้อความในแชตเรื่องอารมณ์/สุขภาพใจเป็น **ข้อมูลอ่อนไหว (มาตรา 26)** ต้องได้ความยินยอมโดยชัดแจ้งแยกรายการก่อนส่งออกจากเครื่อง, ส่งข้อมูลไปต่างประเทศ (เซิร์ฟเวอร์ LLM) ต้องมีมาตรการคุ้มครองที่เพียงพอ (มาตรา 28–29), ทำสัญญาประมวลผลข้อมูลกับ Cloudflare และผู้ให้บริการ LLM, ต้องมี DPO เมื่อกิจกรรมหลักเกี่ยวกับข้อมูลอ่อนไหว, แจ้งเหตุละเมิดภายใน 72 ชั่วโมง, ผู้ใช้ลบข้อมูลได้ง่าย, ห้ามนำไปใช้โฆษณา/ขาย, B2B นายจ้างห้ามเห็นรายบุคคล
- **พ.ร.บ.เครื่องมือแพทย์ / อย.**: ถ้าโฆษณาหรือออกแบบให้ AI "วินิจฉัย ติดตาม รักษา บรรเทาโรค" อาจกลายเป็น SaMD ต้องขึ้นทะเบียน ใช้ภาษา wellness เท่านั้น
- **สหรัฐอเมริกา (ระดับรัฐ)**: Illinois ห้าม AI ให้บำบัดหรือการสนับสนุนทางอารมณ์เชิงบำบัด (Wellness and Oversight for Psychological Resources Act, 2025); Nevada และ Utah มีกฎหมายเรื่องแชตบอตสุขภาพจิต (ข้อจำกัดการอ้างตัวและการเปิดเผยว่าเป็น AI); New York และ California (SB 243) บังคับ AI companion ให้บอกว่าเป็น AI ซ้ำเป็นระยะ มีโปรโตคอลตรวจจับความคิดฆ่าตัวตายและส่งต่อบริการวิกฤต และรายงานบางรายการ → **พิจารณาปิดโหมด AI สำหรับผู้ใช้ในสหรัฐฯ**
- **สหภาพยุโรป**: GDPR มาตรา 9 (ข้อมูลสุขภาพ), EU AI Act หน้าที่โปร่งใส (แจ้งว่ากำลังคุยกับ AI) และข้อห้ามระบบรู้จำอารมณ์ในที่ทำงาน/สถานศึกษา (เกี่ยวข้องถ้าขาย B2B)
- **แนวทางวิชาชีพ**: APA health advisory (พ.ย. 2025) เรื่องแชตบอตและแอป wellness: บอกซ้ำว่าเป็น AI, ห้ามอ้างคุณวุฒิ, ลดการพึ่งพา, มีโปรโตคอลวิกฤตที่ทดสอบแล้ว
- **ผู้เยาว์**: Hikari รับเฉพาะ 18+ แต่ควรมีมาตรการกรณีผู้เยาว์ใช้ (คดีต่างประเทศส่วนใหญ่เกี่ยวกับวัยรุ่น) สายเด็ก 1387 มีในหน้าต่างช่วยเหลือแล้ว

## 7. ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `game-chat.js` | เครื่องยนต์ (เดาเรื่อง, เลือกคำตอบไม่ซ้ำ, ความปลอดภัย, Local/Remote provider) + หน้าจอแชต |

| `config.js` | `CHAT_ENDPOINT` (คอมเมนต์ไว้ = ปิด) |
